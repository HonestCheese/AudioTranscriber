# AudioTranscriber

Android-приложение для локальной расшифровки русскоязычных разговоров. Записывает и импортирует аудио, автоматически разделяет речь на участников, сохраняет реплики с временными метками и экспортирует результат в JSON.

Финальная конфигурация: **GigaAM v3 E2E RNNT → Reverb v1 + ERes2NetV2 → временное сопоставление слов → необязательное узнавание голосов через TitaNet → реплики**. Используется исходная аудиодорожка **Original**, Viterbi отключён.

## 3. Инструкция по установке и использованию

### Требования и установка

- Телефон **Android 8.0 или новее (API 26+)**, архитектура **arm64-v8a**.
- Около **1.1 ГБ свободного места для установки основных моделей**, помимо скачанного архива. Для обработки нужна дополнительная оперативная память.
- Интернет для первоначального скачивания дополнительных весов. После их установки обработка работает локально.

1. Откройте [проверенную сборку финальной версии в GitHub Actions](https://github.com/HonestCheese/AudioTranscriber/actions/runs/42430390285).
2. В разделе **Artifacts** скачайте **AudioTranscriber-debug** и распакуйте ZIP. Для скачивания может потребоваться вход в GitHub.
3. Перенесите `app-debug.apk` на телефон, откройте его и разрешите установку из выбранного источника, если Android запросит это.
4. При использовании микрофона предоставьте разрешение на запись звука.

**APK в корне репозитория может отличаться от последней сборки.** Приведённая выше ссылка относится к проверенной версии `1.7-final-enrollment`, коммиту `13509f6`.

### Установка моделей

Веса GigaAM **не включены в APK и исходники**. Для первого запуска требуется отдельно подготовленный архив экспорта GigaAM.

1. Скопируйте на телефон полный `…_models.zip` или все семь файлов `android_models.part01` … `android_models.part07`.
2. В приложении откройте **«Аудио» → «Установить модели»** и выберите ZIP либо сразу все семь частей, не переименовывая их.
3. Дождитесь проверки размеров и SHA-256 файлов. Маленький `…_info.zip` для установки не подходит.
4. При первой расшифровке приложение скачает **Reverb v1** и **3D-Speaker ERes2NetV2**. Веса сохраняются в приватном хранилище для дальнейшей работы без интернета.

Ранее подготовленный большой архив подходит: используются три ONNX-файла GigaAM, а старые Pyannote/Titanet из архива не участвуют в основной диаризации. DPDFNet2 в финальном режиме не загружается и не запускается. Отдельный TitaNet Small скачивается только при регистрации голосового профиля или при необходимости использовать сохранённые профили.

При обновлении APK поверх приложения данные сохраняются, если совпадает подпись сборки. Удаление приложения удаляет его приватные модели, профили, записи и расшифровки.

### Обработка и просмотр

1. На вкладке **«Аудио»** нажмите **«Выбрать файл»** или **«Записать»**, затем остановите запись. Форматы декодируются средствами Android; для WAV предпочтителен обычный PCM 16 бит.
2. Нажмите **«Создать расшифровку»**. Приложение само определит число участников. Указывать имена или создавать профили заранее не требуется.
3. Дождитесь завершения этапов обработки. Результат сохраняется и доступен во вкладке **«Обработка»**, аудиозаписи — во вкладке **«Записи»**.
4. При необходимости измените отображаемые имена участников. Нажатие на реплику переводит воспроизведение к соответствующему моменту.
5. Кнопкой экспорта сохраните JSON в выбранное место.

Переключателя трёх аудиовариантов в финальном интерфейсе нет: и распознавание, и диаризация используют **Original**. Исходный аудиофайл не перезаписывается.

### Режим «Поток»

Кнопка **«Поток»** под плеером открывает карточку текущей реплики и участника. С началом звучания слова выделяются синим акцентом приложения. Карточка обновляется при воспроизведении и перемотке; на паузах между репликами показывается соответствующее сообщение.

Карточка не блокирует остальные элементы экрана. Повторное нажатие на кнопку закрывает её. Это просмотр **готовой расшифровки**, а не распознавание микрофона в реальном времени. Для старых результатов без временных меток слов доступен текст реплики; для подсветки нужна повторная обработка.

### Голосовые профили — необязательно

Без профилей приложение разделяет разговор на **«Участник 1», «Участник 2»** и т. д. Профили позволяют узнавать знакомого человека и подставлять его имя.

1. Нажмите **«Добавить голосовой профиль»** и введите имя.
2. Выберите **2–4 независимые чистые записи одного человека**, каждая длительностью **от 2.5 секунды**. В записи должен говорить только этот человек.
3. Дождитесь создания профиля. TitaNet Small при необходимости загрузится автоматически.
4. Обработайте разговор заново: сохранённые профили применяются к новой расшифровке.

Профиль — числовой вектор голоса; он хранится локально отдельно от встречи. Его можно удалить из списка. Если совпадение недостаточно уверенное, приложение сохраняет обычный кластер участника. Старые расшифровки автоматически не перерасчитываются.

### Сборка из исходников

Откройте проект из ветки `master` в Android Studio. Требуются **Gradle JDK 21**, **Android SDK 35**; проект использует Gradle 8.11.1, AGP 8.9.1 и Kotlin 2.1.20. Интернет нужен для получения зависимостей при первой сборке.

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

В Windows используйте `gradlew.bat`. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`. Текущая сборка рассчитана на физический arm64-телефон; x86-эмуляторы не поддерживаются.

## 4. Архитектура решения и применяемые модели

### Компоненты приложения

| Компонент | Назначение |
|---|---|
| Kotlin, Jetpack Compose, Material 3 | Интерфейс записи, плеера, истории и расшифровок |
| `TranscriptionViewModel` и coroutines | Фоновая обработка, прогресс, запрос отмены, состояние при повороте экрана |
| `AudioRecorder`, `AudioPlayer`, `AudioDecoder` | Запись, воспроизведение, декодирование и преобразование в mono Float32 / 16 kHz |
| `LocalTranscriber`, `MelFeatures` | Запуск GigaAM и последовательность этапов обработки |
| `ReverbEres2NetDiarizer` | Сегментация речи, голосовые признаки и автоматическая кластеризация |
| `WordSpeakerAligner` | Назначение говорящего каждому слову по временному пересечению и сборка реплик |
| `TitaNetEnrollment` | Регистрация независимых голосовых профилей и узнавание участников |
| `RecordingStore`, `TranscriptStore`, `ModelInstaller` | Локальные аудиофайлы, результаты и установка моделей |

GigaAM освобождается перед запуском диаризации для снижения пикового расхода памяти. Инференс выполняется на CPU телефона: **ONNX Runtime Android 1.23.2** для GigaAM, **sherpa-onnx 2.0.1** для диаризации и TitaNet. Сеть используется для загрузки весов; аудио и текст на сервер не отправляются.

### Модели и параметры

| Этап | Модель / алгоритм | Зафиксированная конфигурация |
|---|---|---|
| Подготовка аудио | MediaExtractor / MediaCodec, polyphase FIR с Kaiser-окном | Mono, Float32, 16 kHz; оригинал сохраняется |
| Распознавание | **GigaAM v3 E2E RNNT** (`v3_e2e_rnnt`) | Окна 24 s, шаг 23 s, перекрытие 1 s; удаление дублей по середине слова |
| Сегментация | **Reverb v1** | Window shift ratio 0.1; min duration on 0.3 s, off 0.5 s |
| Голосовые признаки диаризации | **3D-Speaker ERes2NetV2** | Модель из официального ONNX-релиза sherpa-onnx |
| Кластеризация | **FastClustering** | Автоматическое число участников (`-1`), threshold 0.63 |
| Назначение слов | Временное пересечение | Максимальное суммарное пересечение по участнику; минимальная доля 0.15 |
| Узнавание зарегистрированных голосов | **NeMo TitaNet Small** | Запросы от 1.5 s; cosine similarity ≥0.30; отрыв от второго кандидата ≥0.06 |
| Сборка реплик | Объединение соседних слов одного участника | Максимальная пауза 0.9 s |

Профиль TitaNet получается усреднением нормализованных векторов отдельных записей с повторной нормализацией среднего. Речевые ходы одного кластера объединяются с паузой до 0.8 s, если между ними нет речи другого участника. TitaNet и ERes2NetV2 используют разные пространства признаков: их векторы не сравниваются друг с другом.

**Viterbi отключён.** DPDFNet2, компрессор и WPE не входят в финальный путь обработки. Эталонные RTTM и эталонное число участников используются только в исследовательском benchmark.

### Сохранение и экспорт

JSON содержит `recording_id`, `sample_rate`, `duration_ms`, `speakers`, `transcript`, `words` и `pipeline`.

- У реплики: `speaker_id`, `start_ms`, `end_ms`, `text`.
- У слова дополнительно: `speaker_id_raw`, `speaker_confidence`, `assignment_source`.
- У участника: `first_seen_ms`, `source`, а при сопоставлении с профилем — `profile_id`.
- Назначения без достаточного пересечения сохраняются как `speaker_unknown`.
- `pipeline` описывает модели и параметры обработки. Старые результаты сохраняют отметку прежнего режима.

## 5. Ограничения решения

- Автоматическое определение участников может ошибаться при похожих голосах, коротких репликах, шуме и эхе.
- Одновременная речь не разделяется на отдельные источники; source separation и выделение целевого говорящего не реализованы.
- Временные метки слов в Android приближённые; возможна неточная синхронизация подсветки.
- `speaker_confidence` — доля временного пересечения, а не калиброванная вероятность нейросети.
- Узнавание по TitaNet требует чистых независимых записей. Пороги 0.30 и 0.06 нуждаются в проверке на реальных встречах; совпадение не гарантирует установление личности.
- Декодированное аудио хранится в памяти. В коде установлен предел **30 минут**, но допустимая длина и скорость обработки также зависят от RAM и CPU телефона.
- Для длительной обработки приложение следует оставлять открытым: foreground service не реализован. Уже запущенный нативный вызов диаризации завершается до остановки по запросу отмены.
- Первоначальная установка не полностью автономна: нужен отдельный архив GigaAM и интернет для дополнительных моделей. После установки инференс работает без сети.
- «Поток» предназначен для прослушивания готового результата. Контекстная LLM и анализ содержания встречи не реализованы.
- Пять синтетических аудиокнижных записей не доказывают такую же точность на реальных бизнес-встречах.

### Финальный исследовательский benchmark

Источник — `AudioTranscriber_Android_ML_Handoff_Final_v1(2).ipynb`, запуск **`run_20261107_221801`**. Проверены пять синтетических русскоязычных записей **mexus/ru-book-mix-10h**: `rec_0055`, `rec_0272`, `rec_0273`, `rec_0437`, `rec_0590`. Ниже приведены сохранённые результаты ноутбука, а не повторный замер Android-приложения.

| Аудиовариант | Верно определено число участников | Macro DER | Macro JER | Средний RTF |
|---|---:|---:|---:|---:|
| **Original — выбран для приложения** | **5/5 (100%)** | **10.74%** | **16.38%** | **1.26** |
| DPDFNet2 | 4/5 (80%) | 13.59% | 20.19% | 1.22 |
| DPDFNet2 + Gentle Compressor | 3/5 (60%) | 14.51% | 23.55% | 1.23 |

DER оценивает ошибки разделения речи на говорящих; JER — ошибку пересечения интервалов по участникам. Macro означает среднее по записям. RTF — отношение времени обработки к длительности аудио: 1.26 соответствует времени обработки около 1.26 длительности записи в условиях этого эксперимента.

Для Enrollment в ноутбуке сообщается:

| Метрика | Результат |
|---|---:|
| Micro word-speaker agreement | 96.5% |
| Покрытие Enrollment | 37.07% |
| Точность среди слов, назначенных профилям | 100% |

В benchmark профили получены из RTTM-окон **тех же записей**. Оценка проводилась на словах с однозначной эталонной привязкой вне enrollment-окон; это не независимый cross-meeting тест. Значение 100% относится только к назначенным профилям словам при указанном покрытии, а не ко всей расшифровке.

В предыдущем сравнении Viterbi изменил **0 назначений на всех пяти записях**, поэтому исключён из финального режима. **WER не измерялся**: для этих записей нет эталонных текстовых транскриптов. Качество, peak RAM, нагрев, стабильность и RTF финальной Android-версии требуют отдельных измерений на целевом телефоне.
