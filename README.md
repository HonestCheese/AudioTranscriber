# AudioTranscriber

Android-приложение для локальной транскрибации русскоязычных разговоров и автоматического определения говорящих. Поддерживает запись, импорт аудио, прослушивание, сохранение расшифровок и экспорт JSON.

## 3. Инструкция по установке и использованию

### Установка APK

1. Скачайте apk файл из корневой директории репозитория
2. Откройте APK и разрешите установку из выбранного источника, если Android запросит это.
3. При записи выдайте приложению разрешение на микрофон.

Нужен телефон **Android 8.0+ (API 26), arm64-v8a**. x86-эмуляторы в текущей сборке не поддерживаются. Веса GigaAM не включены в APK и исходники: для первого запуска нужен отдельно подготовленный архив моделей.

### Сборка из исходников

Требования для сборки:

- Android Studio;
- Gradle JDK 21;
- Android SDK 35;
- Android-телефон arm64, API 26+.

Сборка и unit-тесты:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

### Первичная установка весов

1. Откройте приложение.
2. Импортируйте существующий ZIP с GigaAM или все семь файлов `android_models.part01 … android_models.part07`. Старый архив подходит: если внутри остались Pyannote/Titanet, приложение просто не использует эти лишние файлы.
3. При первом запуске приложение один раз загрузит дополнительные модели:
   - Reverb v1;
   - 3D-Speaker ERes2NetV2;
   - DPDFNet2 (если выбран один из режимов DPDFNet).
4. После загрузки эти файлы остаются в приватном хранилище приложения. Повторная загрузка не нужна.

Для первичной загрузки дополнительных весов требуется Интернет. **Само аудио, текст и результаты обработки не отправляются на сервер**; инференс выполняется локально. Для скачивания моделей приложению выдано разрешение INTERNET.

При повторном обновлении APK поверх установленного приложения данные сохраняются при совпадении подписи. Удаление приложения удаляет его приватные модели и записи. Для GigaAM и дополнительных моделей предусмотрите около 1.1 ГБ свободного места помимо исходного ZIP; обработке также нужна оперативная память.

### Использование

1. Во вкладке **«Аудио»** нажмите **«Выбрать файл»** или **«Записать»**, затем остановите запись.
2. Выберите вариант аудио для диаризации. Начните с **Original**; DPDFNet-варианты применяются только к копии аудио для определения говорящих.
3. Нажмите **«Создать расшифровку»** и дождитесь завершения. Кнопка отмены позволяет запросить остановку.
4. Просмотрите реплики и участников, при необходимости измените имена участников. Результаты сохраняются и доступны во вкладке **«Обработка»**, аудио — во вкладке **«Записи»**.
5. Нажмите на реплику, чтобы перейти к соответствующему моменту аудио. Кнопкой экспорта сохраните JSON в выбранное место.

### Режим «Поток»

Кнопка «Поток» под аудиоплеером открывает встроенную карточку текущей реплики.
Повторное нажатие закрывает карточку. Она не перекрывает экран и не останавливает
плеер. Говорящий и слова обновляются по позиции воспроизведения, включая перемотку
назад; начавшие звучать слова выделяются синим акцентом приложения. На паузах
между репликами показывается «сейчас нет реплики». Для старых результатов без
пословных меток доступен текст реплики, а подсветка — после повторной обработки.
Это режим просмотра готовой расшифровки при прослушивании записи.

## 4. Архитектура решения и применяемые модели

### Компоненты приложения

| Уровень | Компоненты | Назначение |
|---|---|---|
| Интерфейс | Kotlin, Jetpack Compose, Material 3; `HomeScreen`, `TranscriptScreen`, `PlaybackPhrasePanel` | Запись и прослушивание, управление обработкой, просмотр и экспорт |
| Состояние обработки | `TranscriptionViewModel`, coroutines | Фоновая обработка, прогресс, отмена, сохранение состояния при повороте |
| Аудио | `AudioRecorder`, `AudioPlayer`, `AudioDecoder` | Микрофон, плеер, декодирование MediaCodec/MediaExtractor и mono 16 kHz |
| ML-конвейер | `LocalTranscriber`, `MelFeatures`, `ReverbEres2NetDiarizer`, `WordSpeakerAligner` | ASR, диаризация, сопоставление слов и сборка реплик |
| Хранение | `RecordingStore`, `TranscriptStore`, `ModelInstaller` | Локальные аудиофайлы, JSON и проверяемые файлы моделей |

Путь данных: **исходное аудио → mono 16 kHz → GigaAM и диаризация → пересечения временных интервалов → Viterbi → реплики и JSON**. GigaAM освобождается перед запуском моделей диаризации, чтобы уменьшить пиковую нагрузку на память. Для запуска ASR используется ONNX Runtime Android 1.23.2, для диаризации и шумоподавления — sherpa-onnx 2.0.1. Аудио и текст обрабатываются на телефоне; сеть используется для первичной загрузки дополнительных весов.


### Распознавание речи

- **GigaAM v3 E2E RNNT**.
- Частота: 16 kHz, mono; декодирование включает потоковый polyphase FIR ресемплинг с Kaiser-окном (вместо линейной интерполяции).
- Обработка фрагментами по 24 секунды с шагом 23 секунды.
- GigaAM всегда получает оригинальную аудиодорожку.
- Слова и их временные метки извлекаются из RNNT-токенов.

### Диаризация

Используется та же конфигурация, что и в `AudioTranscriber_Final_ML_Pipeline_v1_fixed.ipynb`:

| Компонент | Конфигурация |
|---|---|
| Segmentation | Reverb v1 |
| Speaker embeddings | 3D-Speaker ERes2NetV2 |
| Clustering | FastClustering |
| Число говорящих | Автоматически (`-1`) |
| Threshold | `0.63` |
| Window shift ratio | `0.1` |
| Minimum duration on | `0.3 s` |
| Minimum duration off | `0.5 s` |

### Аудиопредобработка для диаризации

В приложении можно выбрать один из трёх вариантов:

1. **Original** — исходная дорожка без обработки.
2. **DPDFNet mild** — DPDFNet2, ограничение подавления 12 dB.
3. **DPDFNet + gentle compressor** — DPDFNet2 и мягкий компрессор.

Компрессор использует параметры ноутбука: threshold -30 dB, ratio 2:1, максимальное усиление 4 dB, attack 10 ms, release 150 ms.

Обработка применяется только к копии аудио для диаризации. Исходная дорожка не изменяется, а GigaAM всегда работает на оригинале.

В приложении нет эталонных RTTM для пользовательских записей, поэтому оно не может автоматически вычислить DER/JER и выбрать лучший вариант предобработки. По умолчанию выбран Original; варианты можно сравнивать на своих записях.

### Сопоставление слов с говорящими

- Для каждого слова вычисляется доля временного пересечения с интервалами каждого говорящего.
- Сохраняется исходное назначение `speaker_raw`.
- Внутри коротких речевых групп применяется Viterbi-сглаживание с penalty `0.7`.
- Минимальное пересечение: `0.15`.
- Группы разделяются при паузе более `0.8 s` или после конца предложения.
- Слова без достаточного пересечения остаются `speaker_unknown`.
- Реплики объединяются при одинаковом говорящем и паузе не более `0.9 s`.

Экспорт JSON содержит список участников, реплики, слова, исходные и сглаженные метки говорящих, confidence и параметры pipeline.


## 5. Ограничения решения

- Параметры диаризации взяты из benchmark на 10 синтетических русскоязычных записях с RTTM. Это не гарантия такой же точности на реальных совещаниях.
- В текущем приложении нет эталонной разметки, поэтому DER/JER на пользовательской записи не вычисляются.
- Gentle compressor выравнивает общий mono-микс и не может отдельно усилить тихого участника.
- Одновременная речь, сильное эхо, короткие реплики и шум могут приводить к ошибкам кластеризации.
- Speaker Enrollment и сопоставление голосов с заранее известными участниками пока не реализованы.
- Временные метки слов приблизительные; качество нужно проверять на физических устройствах и реальных записях.
- Декодированная запись хранится в памяти; в коде установлен предел длительности 30 минут. Скорость, расход памяти, нагрев и возможность обработки длинных записей зависят от телефона.
- Для длительной обработки приложение следует оставлять открытым: отдельный foreground service не реализован.
- Отмена проверяется между шагами; уже запущенный нативный вызов диаризации должен завершиться до остановки.
- «Поток» показывает готовую расшифровку при воспроизведении, а не выполняет распознавание микрофона в реальном времени.
- Confidence слова вычисляется из временного пересечения и не является калиброванной вероятностью нейросети.

### Проверка качества и границы выводов

Эти проверки подтверждают сборку и отдельные алгоритмы, но не заменяют измерение качества распознавания и диаризации на телефоне. Пользовательская проверка интерфейса получила положительный отзыв; формализованного протокола с измерениями скорости, памяти, WER и DER для физического устройства в репозитории нет.

В исследовательском этапе использовались синтетические русскоязычные записи **mexus/ru-book-mix-10h** с RTTM. В переданном ML-handoff для Reverb + ERes2NetV2 сообщались следующие исторические результаты на десяти записях:

| Порог кластеризации | Верно определено число говорящих | DER | JER |
|---|---:|---:|---:|
| 0.50 | 30% | 20.93% | 25.29% |
| 0.60 | 70% | 13.98% | 20.28% |
| 0.65 | Не указано | 14.77% | 23.21% |

Это результаты исследовательского Python-конвейера, приведённые из `AudioTranscriber_ML_Handoff_2026-11-07(2).json`, а не повторный замер Android-приложения. Исходные отчёты этого benchmark в текущем репозитории не приложены. Они не доказывают ту же точность на реальных совещаниях.

**Текущий порог приложения — 0.63.** В отдельном исследовательском сравнении четырёх записей он дал верное число участников на 2 из 4 записей; для других проверенных порогов 0.61, 0.62 и 0.64 сообщалось 1 из 4. Полных DER/JER для текущего порога и Android-сборки в доступном handoff нет; WER не измерялся. Выбор порога не использует эталонную разметку при обработке пользовательских файлов.
